# Эврика | ИИ-консультант EdPalm

Эврика разрабатывается для консультаций по образовательным продуктам EdPalm. Планируемый сценарий: выяснить потребности клиента, помочь выбрать подходящий продукт и предложить следующий шаг, включая обращение к менеджеру.

## Статус проекта

Подготовлена вторая итерация терминального прототипа: подключение к LLM через Polza.ai, каталог из 51 карточки, правила консультации и локальная карточка обращения. Ядро диалога отделено от канала общения; история сохраняется вместе с краткой памятью.

Код подготовлен, но приложение и тесты ещё не запускались. Качество рекомендаций, работа API и расходы не проверены. Это версия для проверки на вымышленных диалогах, не готовый клиентский сервис.

Telegram, Bitrix24, оплата, выдача доступов и напоминания пока не подключены. Неизвестные условия и расхождения цен в каталоге требуют согласования с заказчиком.

## Планируемые возможности

| Задача | Как должен работать консультант |
|---|---|
| Выяснить потребности | Задать уточняющие вопросы и сохранить ответы в контексте диалога |
| Подобрать продукт | Предложить подходящий вариант по согласованному каталогу и правилам рекомендаций |
| Ответить на вопросы | Использовать утверждённую базу знаний о продуктах и условиях обучения |
| Продолжить разговор | Учитывать предыдущие сообщения и уже полученные сведения |
| Передать обращение менеджеру | Сохранить историю и сведения о запросе для продолжения консультации |
| Сопроводить следующий шаг | После подключения необходимых сервисов направить клиента к оформлению и учитывать подтверждение оплаты |

## Этапы разработки

| Этап | Содержание | Результат для проверки |
|---|---|---|
| 1. Подготовка сценариев | Согласовать каталог, базу знаний, вопросы клиенту и правила передачи менеджеру | Набор сценариев и ожидаемых ответов |
| 2. Диалоговый прототип | Подключить Polza.ai, отделить логику консультации от канала общения, добавить интерфейс в терминале | Диалоги с моделью, которые можно проверить без подключения клиентских каналов |
| 3. Логика продаж | Добавить квалификацию клиента, рекомендации и проверку ответов; разделить краткую память модели и историю для менеджера | Проверка консультаций по согласованным сценариям |
| 4. Telegram-бот | Подключить Telegram Bot API после проверки диалогового прототипа | Версия для согласованного пилота в Telegram |
| 5. Интеграции | Подключить Bitrix24, Salebot, образовательный портал и подтверждения оплаты в согласованном объёме | Проверка передачи обращений и статусов между системами |

Сроки и состав пилота предстоит согласовать после уточнения сценариев и доступов к внешним системам.

## Планируемые интеграции

- **Polza.ai:** доступ к языковой модели для диалогов.
- **Telegram Bot API:** общение с клиентами через бота.
- **Bitrix24:** передача обращений и сведений для отдела продаж.
- **Salebot:** связь с существующими сценариями чат-бота.
- **Образовательный портал и оплата:** переход к оформлению и получение подтверждённых статусов.

Адаптер Polza.ai написан для терминального режима, но ещё не проверен реальными запросами. Остальные интеграции предстоят; автоматическая передача обращений и повторные сообщения клиентам отключены.

## Что необходимо согласовать с заказчиком

- Каталог продуктов, актуальные условия и материалы для базы знаний.
- Вопросы для квалификации клиента и правила выбора рекомендаций.
- Ситуации, в которых консультацию продолжает менеджер, и состав передаваемых сведений.
- Правила хранения истории диалогов и работы с клиентскими данными.
- Приоритет интеграций, необходимые доступы и ответственных за подключение.
- Сценарии проверки и критерии готовности к пилоту.

Первым результатом для совместной проверки служит подготовленный код терминального прототипа. Подключение Telegram и остальных систем последует после согласования его поведения.
